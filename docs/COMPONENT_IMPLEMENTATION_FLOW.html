Component Architecture

컴포넌트 구현 시각화 문서

이 문서는 과제의 Component 요구사항에 맞춰 현재 프로젝트가 컴포넌트를 어떤 구조로 구현했는지를 설명합니다. 핵심은 FunctionComponent, 루트 상태, props-only 자식 컴포넌트 구조입니다.

FunctionComponent
RootApp
StopwatchCard
Props-only Child

1. 전체 컴포넌트 구조

flowchart TD
    A["mountApp()"] --> B["new FunctionComponent(RootApp, container)"]
    B --> C["FunctionComponent 인스턴스"]
    C --> D["mount()"]
    D --> E["RootApp() 실행"]
    E --> F["StopwatchCard(props) 호출"]
    F --> G["VNode 트리 반환"]
    G --> H["실제 DOM 마운트"]

6. StopwatchCard 내부 구성

flowchart TD
    A["StopwatchCard(props)"] --> B["formatStopwatch(elapsedMs)"]
    A --> C["formatStopwatch(latestLapMs)"]
    A --> D["버튼 텍스트 결정"]
    A --> E["랩 목록 렌더"]
    E --> F["lap-row class 계산"]
    E --> G["empty-laps 또는 laps-body"]

StopwatchCard는 상태를 갖지 않고, 부모가 넘긴 props만 이용해 화면을 그립니다. 과제의 stateless 자식 요구사항을 그대로 반영한 구조입니다.

9. 과제 요구사항과 연결하면

flowchart TD
    A["과제의 Component 요구사항"] --> B["반드시 함수형 컴포넌트"]
    A --> C["FunctionComponent 클래스 필요"]
    A --> D["hooks 배열 필요"]
    A --> E["mount / update 필요"]
    A --> F["루트 상태 관리"]
    A --> G["자식은 stateless props-only"]

    B --> B1["RootApp / StopwatchCard"]
    C --> C1["FunctionComponent.js"]
    D --> D1["this.hooks = []"]
    E --> E1["mount() / update()"]
    F --> F1["RootApp state"]
    G --> G1["StopwatchCard(props)"]
이 프로젝트의 컴포넌트 구조는 FunctionComponent가 함수형 컴포넌트의 실행 컨텍스트를 맡고, 루트 RootApp이 상태와 로직을 모두 관리하며, 자식 StopwatchCard는 props만 받아 화면을 그리는 stateless 구조입니다.
